# Как сдавать

## Автопроверка

1. Получить от организаторов доступ к API для локального прогона. На платформе он подставляется автоматически.
2. Проверить на публичных вопросах, что ответы содержат правильные выводы, даты и ссылки. Текущий пакет ещё не прошёл реальную генерацию.
3. На странице «Первый тур», вкладка «Загрузить решение», выбрать `output/opora-submit.zip`.
4. Дождаться результата в истории решений. Записать время МСК, версию коммита и оценку. Не расходовать следующие попытки без анализа ошибок.

По регламенту: ZIP до 128 МБ; 5 попыток в сутки на команду со сбросом в 00:00 МСК; 20 минут; 8 CPU; 16 ГБ RAM. Структура ZIP плоская, точка входа solution.py. Платформа передаёт questions.csv и knowledge-base.zip. Вручную загружать submission.csv вместо скрипта не нужно.

Score = 0.7 * Match Rate + 0.3 * Win Rate. Выдуманный факт обнуляет вопрос. Это оценка автоматического этапа, а не вся оценка проекта.

## Финальная сдача

Кейс допускает PDF со ссылкой на репозиторий на первом слайде либо ZIP с кодом, документацией и PDF. Для этого пакета предпочтителен `output/opora-final.zip`: включает корпус для воспроизводимости локальной проверки, исходники, Docker и презентацию. Учебные данные не публикуются на GitHub.

Первый слайд содержит репозиторий и порядок проверки. В публичном репозитории перед сборкой нужно выполнить `python fetch_materials.py`, так как архив базы хранится у организаторов. В финальном ZIP база уже есть. Если организаторы требуют буквально все файлы при сдаче PDF через репозиторий, используйте финальный ZIP.

После дедлайна зафиксировать commit SHA и не изменять сданную версию. Дедлайн в предоставленных материалах не указан. Адрес страницы сдачи в скриншотах не виден. Пока ни одна попытка на платформе не потрачена.

## Допуск к экспертной оценке

Нужны одновременно: балл LLM-судьи выше нуля, работающий веб-чат, полный комплект финальных материалов. Собранный пакет сам по себе не подтверждает допуск: результат платформы ещё предстоит получить.
