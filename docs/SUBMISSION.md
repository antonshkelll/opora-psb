# Сдача версии 3

1. Скачайте `opora-submit-v4.zip` из релиза v4.0.0. Не распаковывайте и не переименовывайте внутренние файлы.
2. На странице кейса откройте «Первый тур» -> «Загрузить решение» -> «Выбрать файл».
3. Выберите именно `opora-submit-v4.zip`. Это скрипт решения, не готовый CSV, не PDF и не финальный комплект.
4. Дождитесь завершения в «Истории решений». Сохраните оценку и время. На скриншоте старой версии было 24; новый результат сравнивается с ним.
5. Не расходуйте следующую попытку на тот же код: кнопка скачивания возвращает ваш архив, а не поответный отчёт. Если платформа даёт отдельную ошибку/лог, сохраните его.

API, модель, `questions.csv` и архив базы подставляет платформа. Собственный ключ и запущенная на вашем компьютере Ollama для сдачи не нужны. В ZIP четыре корневых файла: solution.py, core.py, engine_v4.py, requirements.txt. Архив меньше 128 МБ; лимиты среды: 20 минут, 8 CPU, 16 ГБ RAM, 5 попыток/сутки, сброс в 00:00 МСК.

Оценка: 0.7 * Match Rate + 0.3 * Win Rate. Выдуманный факт обнуляет вопрос. Локальная проверка на 18 открытых примерах не позволяет предсказать эту оценку.

Для финальной экспертной сдачи используйте `opora-final-v4.zip`: код, учебная база, инструкции, тесты, Docker и PDF. Первый слайд содержит ссылку на репозиторий и порядок проверки. Презентация также доступна по публичной ссылке `https://antonshkelll.github.io/opora-psb/deck.html`.

Точный дедлайн в предоставленных материалах не указан. После сдачи фиксируйте версию v4.0.0 и SHA коммита. Новый балл подтверждает только результат платформы; автоматическая загрузка от вашего имени в этой проверке не выполнялась.
